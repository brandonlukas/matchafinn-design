Matcha + Finn figure design system

One visual language for every figure across the Matcha/Finn repos. This page renders what STYLE.md says, so we can argue about what we see. Everything on white “paper” cards is shown as it prints; page chrome is deliberately untinted so it doesn’t colour the judgement.

§1

Principles

Swiss discipline (hairlines, restraint, fewest sizes); the colour is ours.

  1. Colour encodes identity, never emphasis. A hue means one thing across the whole paper. Nothing is coloured to look important.
  2. Grey carries everything that is not the claim — backgrounds, non-hits, nulls, context. Colour is reserved for what the method did.
  3. The null or threshold is drawn, not asserted — dashed cutoffs, grey null tracks, a-priori constants labelled on the plot.
  4. One coordinate system, reused — a row order or locus window fixed once so panels compare without being told to.
  5. Frames are nearly absent — hairline axes, no gridlines, no boxes, no legend frames; panel titles as plain text.
  6. Schematics carry real thumbnails, not icons, drawn in the same tokens as the data panels.
  7. Constraints first — every glyph ≥ 5 pt at 1:1, verified by a script, never eyeballed.
§2

Colour tokens

Names are semantic. Scripts reference tokens (pal$matcha, scale_colour_method()), never hex literals. Muted throughout; saturation belongs to the two heroes. Reading: colour = the hero acted; slate = a competitor; rule-grey = nothing tried.

Heroes — the two method families settle

Finn is indigo everywhere. Deep tints (#1F6F52, identity matcha) are for screen text and slides, not for marks.

Decided 2026-08-29: Finn stays #33517F. A brighter indigo lands on hit’s hue (277° vs 280°); the dark one reads as authoritative, and keeps 20 L* below matcha.

Neutrals — one family, chroma 0 settle

True greys (C = 0), each at the same lightness as the green-tinted value it replaces (muted L 50, slate L 63, rule L 88), so nothing already exported shifts in weight. Panels export transparent and are always assumed to sit on white — there is no ground token. Two or more baselines in one panel → lightness ramp muted → slate → rule with shape/linetype as the redundant channel; never a second hue.

Decided 2026-08-29: the green-tinted family (#6B7A71 · #8C9AA6 · #D6DED8) retires; neutrals are pure grey at matched lightness. ground is dropped — four neutrals, not five. Only the heroes and modality carry hue.

Modality held

Lightness (amber light, plum dark) is the CVD backup; shape (ATAC ▲ / ChIP ●) where points mix.

Accents — exactly two settle

red is the one red (the annual-review query red): the query mark (an all-stroke asterisk, so it hides nothing) and any “disease/case” arm — the hue absent from viridis. hit marks a same-context hit in a ranked list; misses are slate.

Arms — case / control settle

Case is always rose. Control is teal when it is a compared arm, slate when it is context. Disease vs healthy (fibroid vs myometrium) gets its own pair because red is the query and must not double as “disease”. Rose (~350°) and teal (~195°) are the only hue arcs not already spoken for — everything else sits within ~45° of a hero, a modality, or an accent. scale_colour_arm(), context = TRUE for the slate form.

A · compared arms — rose vs teal. Both arms are claims (fibroid vs myometrium); 14 L* apart and opposite in a/b, so it survives every CVD type. The diverging ramp below reuses the same endpoints, so “more in disease” and “disease arm” are one hue.
B · control as context — rose vs slate. Principle 2: grey carries what is not the claim. Use when the healthy arm is a reference the case is read against, not a comparison — or when a panel already carries teal for something else.

Teal ↔ rose replaces red ↔ blue for the ramp: with red = query and hit = blue, a red↔blue colourbar would borrow both accents’ meanings. Rose ↔ teal keeps each hue to one job. Rose and red share L* ≈ 48 and should never share a panel — they don’t: the query lives in embeddings, case/control in differential panels.

Tissue / many-category held

8 desaturated hues + rule for “Other” (context, not a competitor); cap at 8. Only where colour is the sole encoder and illustrative (a UMAP by tissue). These hues are not available for other meanings. “Other” had drifted from grey80 (annual-review tag) to slate, which made the grey 8th hue unreadable; on rule grey the full 8 hold.

Family ramps — ordered sub-categories settle

When a category splits into ordered sub-categories, the sub-categories are a lightness ramp of the parent hue — dark for the focal / nearest / first, light for the rest — never new hues. New hues are spent only on genuinely different families. (This is what the ClairS and rE2G moodboard figures do: precision/recall/F1 as three tints of one method colour; predictor families as ramps.) Baselines already follow it (muted → slate → rule); modality is a two-step ramp across two hues.

cCRE classes — proposal settle

ENCODE SCREEN v4 classes for a stacked composition bar (matchafinn-apps, Fig 6). Three families, not eight colours: PLS → pELS → dELS is ordinal by distance to TSS, so it is one olive ramp (dark at the promoter, light distal — and light for dELS, which is 56–93 % of every bar); CTCF / CA / TF is the second family (TF-binding-defined rather than histone-defined), one dusty blue; no cCRE is context, rule. Olive (~115°) is the last hue arc not within 40° of a token; dusty blue is low-chroma (C 16) so it does not read as hit.

Real composition from dars_ccre_summary.json: DAR tiers × cCRE class. Segments ordered PLS → pELS → dELS → CTCF/CA/TF → none from the baseline, so the ramp reads as one bar filling up from the promoter outward.

The ENCODE SCREEN colours (red / orange / yellow / blue / pink) are deliberately not used: they are saturated identity colours in another system and would collide with red, atac and hit here.

Signal is an amber ramp that passes through the atac token (white → atac → dark umber), so an accessibility heatmap is visibly “ATAC-coloured” — the same instinct as YlOrRd, but it ends in umber, not red, so it never quotes red. Score is viridis for any abstract 0–1 quantity; below zero collapses to rule grey on the same bar (scale_fill_cosine()). Co-binding r is a score: it is one-directional in practice (nearly all r ≥ 0), so it takes the score ramp with r < 0 → rule, not a diverging ramp — diverging is reserved for the arms. p_adj also takes the score ramp (as −log₁₀), with count as size: the blue → magenta → red default of clusterProfiler dot plots is a two-ended ramp on a one-ended quantity and would quote both hit and red.

The tokens in use

Three mock panels drawn only from the tokens above (synthetic data), at roughly 2× print size. This is the language; the real panels should look like these.

§6

Legends and labels

  • heldDirect labels beat legends. Label clusters/lines on the plot (muted, fs_small) when ≤ 8 items fit; a legend only when they don’t.
  • heldEach legend once per figure; a key shared by two panels lives between them.
  • heldPlacement priority: inside the panel’s dead space → above the panel, horizontal, left-justified → right of the panel. Keys 7 pt. Colourbars vertical at the right, 6 pt wide, one per figure. No legend background or frame.
  • figure-specific?Row/track labels sit left as horizontal strips, vertically centred on their row. Ranks as #1; context names in muted. — Track/rank conventions belong to the signal + ranked-list panels; general enough to keep, but phrase as “row labels” not “track labels”?

Heatmaps — the one place a frame is allowed held

deeptools-style (now what fig6/a_dar_heatmap.R does): profile above in the row-group colours, ink 0.4 pt frame around each raster (a raster needs an extent), a 2 mm row-group strip on the left in the group’s own token (here the arms), the signal ramp, one colourbar at the right.
  • settleFrame: ink 0.4 pt around the raster only — not around the profile, not around the figure. Principle 5 still holds everywhere else.
  • settleRow groups: a left strip, 2 mm, filled with the group’s token (arms, cCRE class, tissue), label rotated inside it in fs_small white or ink by contrast. The profile plot above uses the same colours — the strip is its legend.
  • settleResolution: rasterise at ≥ 600 dpi with ≥ 1 bin per output pixel (deeptools --binSize small, or interpolate = TRUE), so the image reads as continuous, not blocky. Rows sorted by mean signal, descending.
  • settleColourbar: one per figure, right, 6 pt wide, ticks in fs_small; a shared scale across the panels it serves.
§7

Layout and assembly

  • heldCanvas 180 mm wide, ≤ 225 mm tall. Panels exported at their final mm box, placed 1:1 in Inkscape, never scaled.
  • heldGrid: 8 mm gutters; align axis origins across a row and left edges down a column; one baseline per row.
  • heldPanel letters: 8 pt Arial Black, lowercase, top-left, a fixed 1 mm outside the panel’s ink box. Inkscape only.
  • figure-specific?“Three acts per method figure: mechanism → one worked instance → the population.” — a narrative template for the method figures, not a visual rule. Move to the manuscript’s assembly notes.
  • figure-specific?Zoom (d→e): source box ink 0.4 pt; two rule-grey 0.25 pt leaders to the zoom’s corners. — The magnifier convention is general; the panel letters are not.
  • figure-specific?Schematics: 1 unit = 1 mm, flat fills, 0.18 pt outlines, closed 22° arrow heads. — General enough to keep; drop the a_schematic.py file reference.
