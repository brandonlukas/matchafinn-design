Matcha + Finn figure design system

One visual language for every figure across the Matcha/Finn repos. STYLE.md holds the rules and tokens.json the values; this page renders both so the system can be judged by eye. Everything on a white “paper” card is shown as it prints; the page chrome is deliberately untinted so it does not colour the judgement.

§1

Principles

Swiss discipline (hairlines, restraint, fewest sizes); the colour is ours. Exemplar: scE2G (Nature Genetics 2026, refs/mood/sce2g-2026.pdf) — our tokens, its discipline.

  1. Colour encodes identity, never emphasis. A hue means one thing across the whole paper. Nothing is coloured to look important.
  2. Grey carries everything that is not the claim — backgrounds, non-hits, nulls, context. Colour is reserved for what the method did.
  3. The null or threshold is drawn, not asserted — dashed cutoffs, grey null tracks, a-priori constants labelled on the plot.
  4. One coordinate system, reused — a row order or locus window fixed once so panels compare without being told to.
  5. Frames are nearly absent — hairline axes, no gridlines, no boxes, no legend frames; panel titles as plain text.
  6. Schematics carry real thumbnails, not icons, drawn in the same tokens as the data panels.
  7. Constraints first — every glyph ≥ 5 pt at 1:1, verified by a script, never eyeballed.
§2

Colour tokens

Names are semantic. Scripts reference tokens (pal[["matcha"]], scale_colour_arm()), never hex literals. Muted throughout; saturation belongs to the two heroes. Reading: colour = the hero acted; slate = a competitor; rule-grey = nothing tried.

Heroes — the two method families settle

Finn is indigo everywhere (a brighter indigo would land on hit’s hue; the dark one reads as authoritative and keeps 20 L* below matcha). Deep tints (#1F6F52, identity matcha) are for screen text and slides, not for marks.

Neutrals — one family, chroma 0 settle

True greys (C = 0) at matched lightness (muted L 50, slate L 63, rule L 88). Panels export transparent and always sit on white — there is no ground token. Two or more baselines in one panel → lightness ramp muted → slate → rule with shape/linetype as the redundant channel; never a second hue.

Modality held

Lightness (amber light, plum dark) is the CVD backup; shape (ATAC ▲ / ChIP ●) where points mix.

Accents — exactly two settle

red is the one red: the query mark, an all-stroke asterisk so it hides nothing — the hue absent from viridis. It is never “disease”; that is the case arm below. hit marks a same-context hit in a ranked list; misses are slate.

Arms — case / control settle

Case is always rose. Control is teal when it is a compared arm, slate when it is context. Rose (~350°) and teal (~195°) are the only hue arcs no other token occupies; 14 L* apart and opposite in a/b, so the pair survives every CVD type. scale_colour_arm(), context = TRUE for the slate form.

A · compared arms — rose vs teal. Both arms are claims (fibroid vs myometrium). The diverging ramp below reuses the same endpoints, so “more in disease” and “the disease arm” are one hue.
B · control as context — rose vs slate. Principle 2: grey carries what is not the claim. Use when the healthy arm is a reference the case is read against, not a comparison.

Rose and red share L* ≈ 48 and never share a panel: the query lives in embeddings, case/control in differential panels.

Tissue / many-category held

8 desaturated hues + rule for “Other” (context, not a competitor); cap at 8. Only where colour is the sole encoder and illustrative (a UMAP by tissue). These hues are not available for other meanings.

Family ramps — ordered sub-categories held

When a category splits into ordered sub-categories, they are a lightness ramp of the parent hue — dark for the focal / nearest / first, light for the rest — never new hues (ramp(token, n)). New hues are spent only on genuinely different families. Baselines already do this (muted → slate → rule); a method’s ablations are tints of the method’s hue.

cCRE classes held

ENCODE SCREEN classes for a composition bar. Three families, not eight colours: PLS → pELS → dELS is ordinal by distance to TSS, so it is one olive ramp (dark at the promoter, light for dELS, which dominates every bar); CTCF / CA / TF is TF-binding-defined, one dusty blue (C 16, so it never reads as hit); none is rule. Olive is the last hue arc more than 40° from every token; SCREEN’s own red/orange/yellow/blue would collide with red, atac and hit.

Composition bars via pal_ccre: segments ordered PLS → pELS → dELS → CTCF/CA/TF → none from the baseline, so the ramp reads as one bar filling from the promoter outward. Bars 0.6 of the slot, no outline (§5).

Size is the role, not the value. pt_cloud for every member of a population in the thousands; pt_data for observations you could count; pt_key for the one point per group that summarises it. Set from the token, never a bare number, and the same size in a 40 mm and an 80 mm panel.

Estimate over population. Each group's estimate is a pt_key point in its colour with an uncapped CI; the population it is read against is a pt_data swarm in slate. The discrete axis keeps a tick per row (§5); the continuous axis starts at 0, padded and capped.
  • settleEstimate over population. One panel, both sizes: the claim at pt_key in colour, the context at pt_data in slate. Principle 2 in point form.
  • settleShape: filled circles, no outline. Shape distinguishes only modality (ATAC ▲ / ChIP ●); the query alone is the asterisk.
  • settleSize as an encoding (count in a dot plot) is the one place it varies: area-proportional, scale_size_area(max_size = 2 * pt_key), at most 4 legend breaks; never size and colour for the same variable.
  • settleOverplotting: pt_data goes to α 0.6 first; a population in the thousands is pt_cloud, rasterised at 900 dpi.
§5

Axes and bars

settle

One rule decides both the padding and the corner: a mark that grows from the axis touches it; a mark that sits on a value does not. Bars, areas and ECDFs are flush at zero and the axes meet. Points and lines get padding, and the axes — capped at their outer ticks — leave the corner open, which says that nothing lies on the axis.

Grows from the axis → expand_zero. Bars sit on the baseline, the y line runs 0 → last tick with 5 % headroom above, and the two axes meet at the origin. The x axis is discrete: a baseline spanning every slot, never capped. Rows by value.
Sits on a value → symmetric padding. A point at recall 0 or precision 1 is whole, not halved by the axis line. Both axes are capped at 0 and 1 (axis_cap()) so they do not meet. Same unit on both axes → square.
Log axis. Labels 10n, major ticks only, no minor ticks. A log axis has no zero, so both axes carry padding and cap at their outer ticks.
  • settleZero. A quantity with a true zero (count, fraction, rate, any 0–1 score, signal) starts at 0. Bars never start anywhere else and an axis is never broken: if the range is too wide, a log axis with points, or an inset. Quantities without a zero take the data range; a diverging quantity (log₂ FC, z) is symmetric about 0 with the zero drawn as a dashed muted line.
  • settlePadding. Bars, areas, densities, ECDFs, tracks: expand_zero on the value axis — flush at 0, 5 % headroom, more only to fit value labels. Points and lines: the symmetric 5 % default; bounded scores keep limits = c(0, 1) and the padding sits outside them.
  • settleCap. A continuous axis line runs from the first to the last labelled tick and no further (axis_cap()), so the ends of a bounded axis are always ticks. A discrete axis is a baseline, not a ruler: it spans every category and is never capped (axis_cap(x = FALSE)).
  • settleTicks. Outside, rule weight, 3–5 labelled breaks per axis. Log axes label 10n (scales::label_log()), major ticks only. Discrete axes carry ticks too held: one per category, same length and weight, the label centred on its tick, so a label is tied to its row.
  • settleAspect. Axes in the same unit (precision vs recall, a score against itself) are square (aspect.ratio = 1); otherwise free, set by the mm box.
  • settleTitles. The axis title carries the quantity, then its denominator and the n on their own lines — Recall / (fraction of variants in predicted enhancers) / n = 7,209 variants — so the caption does not have to. Units in parentheses.

Bars and error bars settle

bar_width = 0.6 of the slot, bar : gap = 3 : 2 — one number for vertical, horizontal and stacked bars. A dodged group shares the one slot (position_dodge(width = bar_width)), bars touching, the 0.4 gap kept between groups. Error bars are emphasis lines through the mean mark, no caps.
  • settleWidth 0.6 of the slot (width = bar_width); dodged: position_dodge(width = bar_width) with the same width, so the group fills the slot and the gap stays between groups.
  • settleNo outline. Fill only; a stacked bar’s segments meet with no stroke. Bars sit on the axis line (expand_zero) and never float.
  • settleError bars are emphasis 0.6 pt with no caps (width = 0): a line through the mean mark — the key point, or a 0.6 pt bar across a swarm.
§6

Legends and labels

  • heldDirect labels beat legends. Label clusters/lines on the plot (muted, fs_small) when ≤ 8 items fit.
  • settleAbove eight, number the items: a dashed hairline leader from each curve’s end to its number, set in the item’s colour, and one numbered key per figure. A legend only for discrete categories with no mark to lead from.
  • settleSignificance. In a dot plot, stars sit to the right of the CI (fs_base, ink). Over distributions, a bracket (rule 0.4 pt, 3 pt down-ticks) with the exact P above it in fs_small; stars alone only when more than three comparisons share a panel. Never both.
  • heldEach legend once per figure; a key shared by two panels lives between them.
  • heldPlacement priority: inside the panel’s dead space → above the panel, horizontal, left-justified → right of the panel. Keys 7 pt. Colourbars vertical at the right, one per figure. No legend background or frame.
  • heldRow/track labels sit left as horizontal strips, vertically centred on their row, so a label is tied to one row. Ranks as #1; context names in muted.

Heatmaps — the one place a frame is allowed settle

deeptools-style: profile above in the row-group colours, ink 0.4 pt frame around each raster (a raster needs an extent), a 3 mm row-group strip on the left in the group’s own token (here the arms), the signal ramp, one tick-only colourbar at the right, one word under the pair naming the signal.
  • settleFrame: ink 0.4 pt around the raster only — not around the profile, not around the figure. Principle 5 still holds everywhere else.
  • settleRow groups: a left strip, 3 mm, filled with the group’s token (arms, cCRE class, tissue); the label inside it (white, rotated, fs_small) when the block is tall enough, outside as a horizontal title when it is not. The profile above uses the same colours — the strip is its legend.
  • settleOne stroke weight: frame, profile box + axis and colourbar border are all rule 0.4 pt (ComplexHeatmap: set it once through a parent viewport).
  • settleResolution: rasterise at ≥ 600 dpi with ≥ 1 bin per output pixel, so the image reads as continuous, not blocky. Rows sorted by mean signal.
  • settleColourbar: vertical at the right, 2 mm wide, tick-only (no title), ticks and labels outside in fs_min at even increments, the bar running past the last tick to the clipped max — mfdesign::colourbar(). Its bottom sits on the heatmaps’ bottom edge; one per figure, a shared scale.
§7

Layout and assembly

held
  • heldCanvas 180 mm wide, ≤ 225 mm tall. Panels exported at their final mm box, placed 1:1 in Inkscape, never scaled.
  • heldGrid: 8 mm gutters; align axis origins across a row and left edges down a column; one baseline per row.
  • heldPanel letters: 8 pt Arial Black, lowercase, top-left, a fixed 1 mm outside the panel’s ink box. Inkscape only.
  • heldZoom / magnifier: source box ink 0.4 pt on the full view; two rule-grey 0.25 pt leaders to the zoom’s corners; the zoom shows exactly the boxed region (expand = FALSE).
  • heldFigure narratives (act structure, which panel zooms into which) are per-repo: ASSEMBLY.md.

Schematics settle

Stages are flat rule-grey blocks with a numbered title above; inside, real thumbnails in the data tokens (atac track, embedding with the red query, hit/slate ranked list, finn synthesized track). Connectors are ink; the one coloured arrow is the output, in the method’s hue.
  • settleStages: flat rule-grey blocks (the scE2G stage grey is L* 89, rule is L* 88), no stroke, square corners, a numbered title in fs_base centred above. Flow between stages: ink rule-weight connectors, closed 22° head. 1 unit = 1 mm.
  • heldThumbnails, not icons (principle 6): real data in the data tokens on a white strip inside the stage; 0.18 pt outlines only where a shape needs an edge on the grey.
  • settleOne coloured arrow means an output, in the method’s hue — matcha for the rank, finn for the blend — never a third colour. Everything else that moves is ink.
